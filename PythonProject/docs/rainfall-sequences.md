# 降雨序列与单基线版本

每个研究区只初始化原模拟降雨 INP 对应的 V1。芝加哥雨型、内置真实事件、自定义序列均修改当前版本的降雨条件，并在保存时生成派生版本。工程参数白名单、单个/批量修改、运行和结果归档流程沿用原实现。

## 数据约定

- `start_seconds`：相对模型模拟开始的偏移秒数，不修改模型开始日期。
- `time_step_seconds`：固定的正整数记录间隔，独立于模拟输出步长。
- `values_mm`：每个间隔内的分段雨量（mm），非累计值、非 mm/h 雨强。第 i 项覆盖 `[start + i * step, start + (i + 1) * step)`。
- 最多 10000 条，允许零雨量；非有限数值、负值、空序列被拒绝。
- 序列结束不能超过模拟结束。缩短模拟时长时也会校验继承的降雨，不自动截断或重新生成。
- 预览可汇总绘图，但保存完整序列。序列内容、开始偏移和记录间隔共同参与校验和，过程不同即构成修改。

写入 INP 时统一使用 `VOLUME`，同步雨量计间隔和目标时间序列；保留雨量计名称、引用关系、工程内容及其他时间序列。写入值根据模型单位换算；三种来源共享同一写入器。元信息写在降雨节注释中，版本摘要保存来源、事件 ID、序列校验和，完整序列保存在该版本归档的 INP 内。

金江事件 `jj_real_20260913_2d` 使用独立 JSON 资源：576 个五分钟分段雨量，48 小时共 226.2 mm，峰值 132 mm/h。从原始累计序列逐项差分，模拟结束处的零增量仅作结束标记、不增加第 577 个间隔。原始事件日期保留为资料信息。真实事件本身不可缩放，切到自定义序列后可编辑其副本。老城支持芝加哥雨型和自定义序列，暂无内置真实事件。

## 用户操作

1. 选择研究区和已有工程版本。
2. 在参数面板选择降雨来源。切换来源编辑的是草稿，不跳转到另一个版本；工程参数草稿保持不变。
3. 自定义序列可粘贴一列雨量，或导入 UTF-8 CSV（不超过 1 MB）。两列格式如下：

```csv
offset_seconds,rainfall_mm
0,0
300,1.5
600,0
```

两列偏移相对降雨开始，从 0 连续排列；导入此例时记录间隔须为 300 秒。也支持从表格粘贴制表符分隔的两列。空白行忽略，错误按原文件行号提示。第一版不支持 XLSX、非等间隔、自动插补缺测或多个独立雨量计序列。

4. 检查图形、总量、峰值和覆盖时长。真实事件需要手动将模拟时长设为 172800 秒，并设置满足已有输出点数约束的输出步长（例如 300 秒）。界面不自动修改这些参数。
5. 保存新版本后运行。有未保存的修改时阻止运行当前已保存版本；可先保存或撤销。

## 接口

`GET /api/rainfall-events?study_area=JJ` 返回事件数据，老城返回空数组。此接口与基线版本无关。

`POST /api/rainfall/preview` 校验并生成序列，无数据库或对象存储写入：

```json
{
  "study_area": "JJ",
  "simulation_duration_seconds": 3600,
  "rainfall_options": {
    "mode": "custom",
    "start_seconds": 0,
    "time_step_seconds": 300,
    "values_mm": [0, 1.5, 0]
  }
}
```

响应包含完整序列、来源、总雨量、峰值雨强、覆盖时间和校验和。芝加哥预览复用后端原有生成算法。

保存仍使用 `POST /api/model-versions/{parent_id}/versions`，原来的 `changes`、`simulation_options` 不变；可选的 `rainfall_options` 支持：

```json
{"mode":"design","start_seconds":0,"duration_seconds":3600,"total_rainfall_mm":50}
```

```json
{"mode":"real","event_id":"jj_real_20260913_2d","start_seconds":0}
```

```json
{"mode":"custom","start_seconds":0,"time_step_seconds":300,"values_mm":[0,1.5,0]}
```

省略 `rainfall_options` 就完整继承父版本降雨。序列以 12 位有效数字规范化后保存和比较，相同序列重复提交不会凭空创建新版本。当前版本读取接口返回 `values_mm` 与校验和，支持回显。

`GET /api/models` 返回唯一 `baseline_version_id`，保留兼容字段 `rainfall_inputs`，其中只包含唯一基线。版本列表不再按降雨来源拆分。`GET /api/study-areas/latest-model-versions` 默认仍筛选 `design`，可使用 `rainfall_mode=real|custom|all`；结果下载接口保持不变。

## 升级与验收

1. 同步更新并重启前后端，确保新 JSON 资源随后端发布。没有新增依赖，也不需要新增数据库表或执行专用数据迁移。
2. 已有真实降雨根和其派生版本保留 ID、父子关系、INP 与运行结果，在统一版本列表中继续可访问；不再作为可切换的初始基线，也不再自动补建。无需删除数据库或 MinIO 数据。
3. 浏览器旧缓存自动转换为按研究区保存的版本及结果选择，地图顺序和显隐保持；恢复初始状态统一回到 V1。
4. 联调验收：在已改管径版本上分别应用真实与自定义降雨，确认工程参数继承；只改粗糙度/输出步长时确认序列不变；检验两条同总量不同过程序列均可独立保存；确认旧结果可以查看下载。
5. 本地检查：后端执行 `.venv\Scripts\python.exe -m pytest -q`，前端执行 `npm test` 和 `npm run build`。引擎回归覆盖非整分钟间隔与短起始偏移，防止 SWMM 雨量计间隔错误。

实际引擎对比：原始金江实测 INP 与替换序列后的基线均得到总降雨 226.200 mm、地表径流 156.048 mm（按 RPT 显示精度）。完整 PostgreSQL/MinIO 保存、运行、地图联调仍应在部署环境验收。
